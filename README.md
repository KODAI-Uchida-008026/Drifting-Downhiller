## 工夫したポイント <a id="highlights"></a>

**工夫①：車やコースの自作による世界観の統一**
車やコースなどの素材を外部アセットに頼らず自作し、ゲーム全体の世界観に統一感を持たせました。
また、見た目だけでなく、実際に走行した際の操作感も意識し、ゲーム全体の完成度を高めました。

**工夫②：ドリフト操作と物理挙動の調整**
Rigidbodyを用いた物理ベースの挙動を採用し、車の重さや慣性を表現することで、実際に車を操作しているような感覚を目指しました。
特に、滑る感覚と操作のしやすさのバランスを意識し、グリップや回転速度を繰り返し調整して独自の操作感を実現しました。

**工夫③：タイムアタックに必要なゲームシステムの実装**
タイマー・リザルト・ランキングなどを段階的に実装し、走行から記録の確認まで自然につながるゲームの流れを設計しました。
また、前作からのアップデートを意識し、タイム記録の保存にはJSONを採用しました。プレイ結果を管理できるようにすることで、繰り返し挑戦してタイムを縮める楽しさを意識しました。

## 苦労した点と解決策 <a id="troubles"></a>

**苦労した点①：車の物理挙動とドリフト操作の安定化**
開発初期には、車が地面に埋まったり浮いたりする問題や、コースの凹凸によって車が不自然に回転したり引っかかったりする問題が発生しました。

**解決策**
Colliderのサイズや配置、Inspectorの設定を見直し、問題の原因を特定しました。また、angularVelocity を用いて過剰な回転を抑えることで、車の挙動を安定させ、操作しやすいドリフトを実現しました。

**苦労した点②：スクリプト間の参照とデータ保存の実装**
NullReferenceExceptionやタイマーリセットの不具合が発生し、シーン間のオブジェクト参照やスクリプトの処理構成を見直す必要がありました。また、JSONによるデータ保存では、タイム記録以外の名前やカラー選択の保存にも苦労しました。

**解決策**
オブジェクト参照の設定を確認し、機能ごとにメソッドを整理・分割することで不具合を解消しました。JSONによるタイム記録の保存は実装できましたが、名前やカラー選択の保存については、開発期間を考慮して見送る判断をしました。

[**詳細はエラーログをご覧ください**](#error-log)

## エラーログ <a id="error-log"></a>

| 日付 | エラー内容 | 発生箇所 | 解決方法 | 備考 |
|------|-----------|----------|----------|------|
| 6/11 | 車が落下しない・動かない | Collider | Colliderの設定がオブジェクトのサイズとズレていたことから地面に埋まったり、宙に浮いたりしていた |エラーの際はスクリプトだけでなくインスペクターも良く確認する|
| 6/15 | 車が滑る・スリップする | Collider | Collider上で傾きがあるとその方向へ力が働いてしまう・コース全体を拡大させた際にColliderも大きくなってしまい見た目にでない凸凹が生まれ、そこに引っかかってしまい回転してしまっていた。　これらの事からChatGPTの助言のもとangularVelocityを用いて過度に回転に加速がかからないように常に減速をかけることで解決 | これによりドリフトの回転が緩くなってしまったため再調節・勢いは出ずとも曲がっていく感じ、ドリフト感を演出することができたと思う。 |
| 6/18 | NullReferenceException: Object reference not set to an instance of an object | SceneDirector.cs | オブジェクト参照がオブジェクトのインスタンスに設定されていないとのことなので、インスペクターで取得させた | スクリプトで参照させていたがダメだったのでSerializeField |
| 6/18 | タイマーリセットが上手くいかない | SceneDirector.cs・TimeManager.cs | メソッドを増やし役割を分担させた | 無理にまとめようとするよりも簡単に問題を解決させられた |
